# Security policy

## Reporting a vulnerability

Please avoid publishing a newly discovered vulnerability in WPSXAndroid together with working exploit details before maintainers have had a reasonable opportunity to review it.

When filing a report, include:

- affected revision/version
- device and Android version
- minimal reproduction steps
- expected vs. actual behavior
- whether root/native backends are involved
- logs with secrets and unrelated identifiers removed

Do not include credentials, private keys, captured traffic from third parties, or personal data in public issues.

## Scope

Security issues in bundled third-party components should also be checked against the relevant upstream project and version pinned by WPSXAndroid.
